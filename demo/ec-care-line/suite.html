Six journeys, one engine

Before the visit, after it, and everything that arrives in between.

Each journey watches one part of the patient's path and puts what needs a doctor on the same list. They share one rule book: open and raise only, quote word for word, and only a doctor closes. Every one is a tested prototype, not yet a product; the numbers are on the Evidence tab.

For EC's AI team · LoopBench, 12 Nov 2026

Right where it is checked. Not yet good at wording it hasn't seen.

Every number comes from LoopBench, a simulated Hong Kong clinic year with synthetic patients, three clinic setups and three seeds. Nothing here has run on real clinic data. The weakness is stated first, because it decides what happens next.

The weakness

On wording written after the readers froze, they caught 57 of 133 cases on the first run.

The journey readers are bilingual keyword and pattern rules. They are reliable on the wording they were built on and mostly blind to wording nobody wrote a pattern for. Blind sets were written after each reader was frozen, run once, and the first result kept as it came out. Once fixed, a blind set becomes a development set, so only the first run counts.

What a miss looks like

Verbatim from the blind-set hard fails: emergencies the precare keyword screen did not recognise.

Precare red flags are the most serious gap. Across three blind sets the keyword screen caught 2 of 24 emergencies written in new words, so the patient did not get the fixed 999 reply. In the other five journeys a miss means a missing item while the clinic's own process carries on; no run anywhere closed, downgraded or reassured.

What holds by construction

Checked on every item in every run. Any one is a hard fail and fails the gate.

  • A quote that is not word for word in the record it cites
  • Citing a record the engine could not have seen
  • An item on the wrong patient (namesakes, misfiled faxes)
  • An item with no evidence
  • Any attempt to lower urgency
  • Saying "all clear" while a feed is down

The engine's interface has four writes: open an item, raise urgency, raise an alarm, attest it is not blind. There is no close, dismiss, downgrade or reassure to call. A deliberately broken copy of the engine is run in CI to prove each check fires; the same seed gives the same world, so any change in a number is the change itself.

Core follow-up loops, a full simulated year

Harm-weighted missed loops per 1,000 patient-years (lower is better), seeds 1–3.

Seven loop families (abnormal results, tests never resulted, follow-up recommended, positive screens, referrals, drug monitoring, planned reviews) plus 27 authored traps. 0 hard fails in every cell.

What fixes it, and how we'll know

  • One shared model reader under every journey. It can only add findings or raise urgency, never remove or lower; any field without a verbatim quote is dropped; outputs are cached by prompt version, model and document hash so runs replay exactly. Built, not yet measured.
  • Score it the same way: the same blind sets, plus a held-out set written by a clinician who has not seen the engine. Until then every pass rate here is an upper bound.
  • Shadow mode at one EC clinic before any patient-facing use: the engine reads, nobody acts on it, and its list is compared with what the doctors did.
  • Not yet done for production: clinical safety case and hazard log, privacy impact assessment (PDPO), security review and penetration test, monitoring and on-call, usability testing with EC doctors, an adapter for EC's EMR.
